# Design Guidance

[DESIGN.md](../DESIGN.md) owns the project's visual language. Use the
[design workflow](../workflows/design-development.md) when establishing or revising
it. For web projects, start with the [web readiness checklist](../workflows/web-readiness.md);
it routes to requirements by task. This index is a document map, not another checklist.

- [Placeholder patterns](placeholders.md) - preview text and loading cards.
- [Error states](error-states.md) - HTTP mappings, recovery, forms, and confirmations.
- [Page metadata](page-metadata.md) - titles, descriptions, share images, robots.txt, and public sitemaps.
- [Policy pages](policy-pages.md) - privacy/cookie notices, consent, and valid contact details.
- [Responsive design](responsive-design.md) - viewport selection, RNG sampling, and usefulness ratings.
- [Site icons](site-icons.md) - favicon and app-icon design and verification.
- [Test sitemap](test-sitemap.md) - required post-prototype page/state inventory.

Keep supporting examples and component notes here when intentionally shared;
private captures and draft evidence belong in ignored output folders. Reuse
existing stories, fixtures, or direct views as observation paths. Additional
showcases beyond the required web test sitemap are optional.
